# Content Publishing

## When to apply
- Producing technical guides, changelog narratives, video scripts, or social/newsletter assets from engineering work.
- Reviewing drafts for factual accuracy, audience fit, and broken links.

## Procedure
1. Define target audience, core takeaway, and distribution channel constraints (length, tone, media format).
2. Ground every technical claim, benchmark, and code snippet in verified repository files or observed command outputs.
3. Structure the piece with a clear hook, scannable headings, concrete examples, and an explicit call-to-action or next step.
4. Check formatting, relative/absolute links, alt-text for images, and license/attribution for any third-party quotes or assets.
5. Prepare channel-specific metadata (slug, summary, tags, publish checklist) without publishing externally until explicitly approved.

## Verification
- All code examples and CLI commands match current repository behavior.
- No private tokens, internal URLs, or unverified claims remain in the draft.
